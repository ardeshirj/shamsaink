# Updates over Wi-Fi on the Kobo and the Kindle (docs/DESIGN.md, "Updates over Wi-Fi"), by hand like basics.txt, before
# a release and after a change to reader/update, updates.go or a launch.sh: `make update-e2e`, on the Kindle `make
# update-e2e DEVICE=kindle` (the latest build packed, then this).
# The latest build is the update: devtest serves it from this computer, announced as newer (its version and ".e2e") and
# signed with a key made for the run, which the device in dev mode accepts through dev/update-key (removed after). Wi-Fi
# is on (SSH), so Check asks nothing. First the update kept: downloaded, verified, installed, the reader restarted on it by
# the launcher and the library reached. Then a broken one (its reader exits at once): the launcher puts the latest build
# back and it says so. So a run leaves the device on the latest build, as an install would.
on: kobo kindle
env SHAMSAINK_DEV=1                # dev/update-url and dev/update-key are read in dev mode only
update-serve latest
library
tap library topbar-menu
tap menu settings
tap library-settings update-check
expect-in 30 update: .* is newer than
tap-dialog update-available update-install
expect-in 120 update: .* installed, \d+ files
expect-in 20 launch: update installed: starting
expect-in 60 update: .* reached the library: kept
update-serve broken
tap library topbar-menu
tap menu settings
tap library-settings update-check
expect-in 30 update: .* is newer than
tap-dialog update-available update-install
expect-in 120 update: .* installed, \d+ files
expect-in 20 launch: update to .* undone: it did not reach the library
expect-in 60 update: .* was undone by the launcher
expect library: dialog update notice at
tap 632 1500                       # anywhere: the notice closes
leave
